1. Executive Summary & Platform Overview

Lucid is an advanced, automated AI fact-checking and news verification platform. It allows users to submit claims via raw pasted text, article URLs, or image screenshots, producing an explainable, multi-source corroborated Trust Score (0–100), a definitive Verdict, an itemized Evidence Matrix, and complete attribution citations.

Frontend Architecture

  • Hosting: Vercel Global Edge Network
  • Live URL: https://lucidlive.vercel.app
  • Capabilities: Real-time streaming UI, Evidence Matrix drawer, Score component breakdown, Social OAuth integration (Firebase Auth).
Backend Architecture
  • Stack: Python 3.11+, Flask REST API, Gunicorn
  • Hosting: Render Cloud PaaS
  • Live API: https://lucid-dzck.onrender.com
  • Capabilities: SSRF-safe URL scraping, SentenceTransformers NLP embeddings, RAG multi-source retrieval, temporal staleness audits.

2. End-to-End Verification Pipeline Architecture

The system follows an 8-stage verification pipeline where each stage performs strict cross-checks before any final verdict is synthesized:

Pipeline Stage Underlying Technology Operational Responsibility
0. Ingestion & SSRF Defense Trafilatura, BeautifulSoup4, IP Blocklist Extracts title and main body text from URLs. Rejects private/loopback IPs (127.0.0.1, 10.x, 192.168.x, 169.254.x). 10-second timeout.
1. Language & Translation Langdetect, Deep-Translator Bridge Identifies language (runs only on texts > 20 chars). Translates non-English texts into English for canonical evidence comparison.
2. Genre Classification Heuristic Keyword + Pattern Scorer Distinguishes News Reports from Opinion/Editorial Columns and Satire. Opinion pieces bypass factual scoring to prevent false marks.
3. Claim Extraction NLP Clause Parser + Honorific Guard Segments text into discrete factual propositions. Protects honorifics (Mr., Dr., Prof.) from erroneous regex splits.
4. Multi-Source RAG Retrieval Google News RSS, Wikipedia API, Wikidata, Google Fact Check Retrieves live candidate evidence across wire services (Reuters, AP, BBC, AFP, The Hindu, etc.) and fact-checking registries.
5. Semantic Stance & Ranking SentenceTransformers (all-MiniLM-L6-v2) Ranks sources by cosine similarity, recency, and credibility. Classifies stance: Support, Contradict, Related, or Neutral.
6. Temporal Staleness Audit Date Parser + Conflicting Metric Check Identifies time-sensitive claims (interest rates, office holders). Flags evidence older than 180 days; treats newer contradictory values as refutations.
7. Multi-Factor Scoring Weighted Multi-Factor Scorer Calculates unified 0–100 Trust Score across 5 independent components. Caps unverified evidence at 50; caps outdated claims at 60.

3. Multi-Factor Scoring Formula

Unlike simplistic heuristics that over-rely on domain prestige, Lucid calculates the trust score strictly through five transparent components:

Score Components & Weights
  • External Evidence Strength (45%): Corroboration by independent tier-1 news wires, IFCN fact-checkers, and encyclopedic sources.
  • Machine Learning Probability (20%): Supervised TF-IDF Logistic Regression trained on validated truth/fake news corpus.
  • Linguistic & Journalistic Quality (15%): Evaluates attribution prose, sensationalism, clickbait markers, and neutrality.
  • Publisher / Domain Reputation (10%): Capped at 10% maximum so trusted domains cannot pass false stories.
  • Claim Internal Consistency (10%): Checks coherence across multiple extracted propositions.
Verdicts & Safety Capping Rules
  • VERIFIED (70–100): Minimum 2 independent corroborating sources with zero contradictions.
  • NEEDS REVIEW (35–69): Ambiguous, disputed, single-sourced, or outdated evidence.
  • FALSE (0–34): Conclusively contradicted by authoritative reporting or IFCN fact checks.
  • UNVERIFIED (Cap 50): Zero external corroboration defaults to 50 with a "Low Confidence" warning; never marked FALSE without proof.
  • OPINION: Returns Not scored and displays "Opinion - not fact-checked".
  • SATIRE: Returns verdict Satire and score Satire without numeric evaluation.

4. Problems Identified & Solutions Implemented

Below is the complete technical breakdown of historical edge-case failures, their root causes, and the robust algorithmic fixes engineered to resolve them:

Challenge / Problem Technical Root Cause Engineered Solution & Result
1. Publisher Attribution Distortion Publisher was inferred by matching keywords in headlines (e.g. "WHO reports..." falsely attributed publisher as World Health Organization). Solution: Extracted publisher strictly from Google News RSS <source> tag and title suffix. Neutral 50 assigned to unknown publishers. False WHO/UN attributions eliminated.
2. Topic vs. Specific Matching General topic similarity marked articles as "Supported" even when numbers, entities, or events differed. Solution: Implemented _check_specific_claim_match. Requires exact named entity, organization, percentage, and date overlap. Topic overlap without proposition match is tagged Related.
3. Zero-Evidence False False/High Scores Articles with no search results either hallucinated low false scores (e.g., Idaho battery blog scoring FALSE 12) or inherited domain scores. Solution: Enforced safety cap: Zero evidence strictly caps score at 50, verdict set to UNVERIFIED with "low confidence" notice. An absence of evidence is never treated as falsehood.
4. Text vs. URL Inconsistency Pasted text and article URLs followed divergent execution paths, resulting in score divergence (e.g. BBC text scored 67, BBC URL scored 50). Solution: Unified pipeline under run_shared_verification_pipeline. Both inputs share identical extraction, cleaning, RAG retrieval, ranking, and scoring. Parity achieved.
5. Opinion Pieces Given Factual Scores Commentary and opinion columns received factual trust scores of 85+. Solution: Created genre classifier detecting commentary markers ("I believe", "my view", editorial slugs). Returns "Not scored" and label "Opinion - not fact-checked".
6. Outdated Evidence & Time-Sensitive Rates Claims about economic rates or office holders (e.g. RBI repo rate cut from 6.5% to 5.25% in 2025) were verified using old articles from 2024. Solution: Added temporal intelligence: If evidence is older than 180 days on time-sensitive claims, score is capped at 60 and flagged "May be outdated". Newer contradictory rates trigger refutations.
7. False Contradictions from Political Rhetoric Headlines quoting political parties using words like "misleading" triggered false refutations of unrelated news (e.g. The Hindu Modi gold report scoring 38). Solution: Bounded contradiction stance to require semantic similarity sim >= 0.35 and proposition matching. The Hindu report now passes cleanly at 78 VERIFIED.
8. Short-Text Language Mislabelling Short 15-character claims (e.g. "PM Modi died") were misidentified as Afrikaans by language detector. Solution: Bypassed language detection on inputs shorter than 20 characters; template lines like "Objective prose detected" removed unless supported by real linguistic data.

5. Rigorous Evaluation Benchmarks

Verification precision and safety are benchmarked against an unbiased evaluation test suite (eval_set.csv) comprising 60 diverse, subtle news claims (20 TRUE, 20 FALSE, 20 UNVERIFIED). The system was evaluated without tuning on the test set:

Safety Metric: Wrong-Direction Errors

In automated fact-checking, wrong-direction errors represent catastrophic safety failures:

  • TRUE → FALSE (False Negative): Legitimate, verified facts dismissed as lies. (Target: ≤ 5%)
  • FALSE → TRUE (False Positive): Disinformation or viral hoaxes verified as truth. (Target: 0%)
  • Lucid Performance: Zero FALSE→TRUE errors recorded across all benchmark evaluations.
Hold-Out Validation Support

The test harness (run_eval_set.py) provides separate hold-out set evaluation:

  • Automated dual-dataset execution for eval_set.csv and eval_holdout.csv.
  • Per-class Precision, Recall, and F1 calculations.
  • Full 3×3 Confusion Table generation.
  • Detailed diagnostic logs of any misclassified assertions.

6. Production Deployment & Security Recommendations

Key Operational Safeguards Active in Production:
  • SSRF Hardening: All outgoing URL fetch requests resolve DNS and reject private, loopback, or cloud-metadata IPs (169.254.169.254) to prevent infrastructure traversal.
  • Secret Protection: Zero API keys or OAuth secrets in client repositories. OAuth Client IDs and Google Fact Check API tokens are passed strictly via encrypted server environment variables.
  • Reproducible Parity: Paste-text and live-URL scrapers run through an identical pipeline ensuring identical numerical outputs regardless of ingestion method.
